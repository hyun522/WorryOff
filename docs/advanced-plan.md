# WorryOff Advanced Plan

## 목적

WorryOff 고도화의 큰 방향은 현재의 개인용 외출 전 인증 앱을 유지하면서, 이후 팀 기반 인증과 알림 기능까지 확장할 수 있는 구조를 만드는 것이다.

현재 MVP는 LocalStorage 기반 개인용 앱이다. 고도화 단계에서는 사진 저장을 서버로 이전하고, 개인 모드와 팀 모드를 모두 지원할 수 있도록 데이터 모델과 정책을 확장한다.

## 현재 MVP 요약

- 사용자는 공간 이름을 설정할 수 있다.
- 사용자는 체크리스트 항목을 추가, 삭제, 순서 변경할 수 있다.
- 체크리스트 항목은 사진이 등록되어야 완료 상태가 된다.
- 모든 체크리스트 항목에 사진이 등록되어야 오늘 인증을 완료할 수 있다.
- 하루 인증은 1회만 가능하다.
- 인증 완료 후에는 인증하기 버튼을 숨기고 완료 상태를 보여준다.
- 인증 기록은 최신순으로 저장한다.
- History는 매월 자동 초기화한다.
- MVP 데이터는 LocalStorage에 저장한다.
- MVP는 개인 사용자 1인을 기준으로 한다.

## 공통 정책

### 인증 정책

- 하루 인증은 1회만 허용한다.
- 인증 완료 전에는 등록된 미리보기 이미지를 눌러 사진을 다시 등록할 수 있다.
- 인증 완료 후에는 해당 날짜의 체크리스트와 사진을 수정할 수 없다.
- 인증 완료 시점의 체크리스트와 사진은 History에 snapshot으로 저장한다.
- 체크리스트 변경은 과거 History 기록에 영향을 주지 않는다.
- 과거 History snapshot 보존 정책은 별도 사용자 안내 문구로 강조하지 않는다.

### History 정책

- History 사진 보존 기간은 기존 정책과 동일하게 유지한다.
- History는 매월 자동 초기화한다.
- 월이 바뀌면 이전 달 History는 삭제한다.
- History 기록은 최신순으로 보여준다.
- 인증하지 않은 날은 미완료 기록으로 저장할 수 있다.

### 사진 정책

- 현재 MVP는 사진을 base64 형태로 LocalStorage에 저장한다.
- 고도화 단계에서는 Nest.js 서버를 이용해 사진 저장 문제를 해결한다.
- 프론트엔드는 장기적으로 base64 사진 원본을 LocalStorage에 저장하지 않는다.
- 서버 이전 후 프론트엔드는 사진 URL 또는 photo key를 저장하고 렌더링한다.
- 사진 삭제 정책은 기존과 동일하게 유지한다.
- 사진은 업로드 전 또는 업로드 과정에서 압축을 고려한다.

### 사진 압축 고려사항

- 클라이언트에서 업로드 전 이미지 크기와 품질을 줄일 수 있다.
- 현재 Apps in Toss camera/photos API 사용 시 `maxWidth` 옵션을 통해 이미지 폭을 제한할 수 있다.
- 추가 고도화 시 canvas 기반 압축 또는 서버 측 압축을 검토한다.
- 기본 방향은 사용자 경험을 해치지 않는 수준에서 저장 용량과 업로드 비용을 줄이는 것이다.

## 개인 모드 정책

### 기본 개념

- 개인 모드는 현재 MVP의 기본 사용 방식이다.
- 사용자는 본인 공간의 체크리스트를 만들고 직접 인증한다.
- 개인 모드에서는 사용자 본인이 유일한 인증 담당자다.
- 개인 모드는 향후 팀 구조와 호환되도록, 내부적으로는 멤버가 1명인 Space로 확장할 수 있다.

### 개인 인증

- 개인 사용자는 본인의 체크리스트 항목에 사진을 등록한다.
- 모든 항목에 사진이 등록되면 인증하기 버튼이 활성화된다.
- 인증 완료 후에는 같은 날 다시 인증할 수 없다.
- 인증 완료 전에는 사진을 다시 등록할 수 있다.

### 개인 알림

- 개인 모드 알림은 고도화 작업에서 추가한다.
- 정기 알림은 사용자가 설정한 시간에 오늘 인증을 리마인드한다.
- 개인 모드에서는 콕 찌르기 알림이 없다.

## 팀 모드 정책

### 기본 개념

- 팀 모드는 여러 사용자가 하나의 방 또는 공간을 공유하는 방식이다.
- 초대 받은 사람들끼리 방 이름을 정할 수 있다.
- 팀원들은 함께 체크리스트를 정할 수 있다.
- 팀원들은 오늘의 당번을 정할 수 있다.
- 팀원 모두 설정 페이지에 접근할 수 있다.

### 팀 권한

- 팀원 누구나 팀원을 초대할 수 있다.
- 팀원 누구나 팀원을 삭제할 수 있다.
- 팀원 누구나 방 이름을 수정할 수 있다.
- 팀원 누구나 체크리스트를 추가, 삭제, 순서 변경할 수 있다.
- 팀원 누구나 당번을 변경할 수 있다.
- 별도 관리자 권한은 현재 정책에 포함하지 않는다.

### 팀 인증

- 오늘 당번만 인증할 수 있다.
- 당번이 아닌 사람은 대신 인증할 수 없다.
- 당번이 아닌 사람은 인증 사진을 등록하거나 인증 완료 처리할 수 없다.
- 인증 완료 전에는 당번이 미리보기 이미지를 눌러 사진을 다시 등록할 수 있다.
- 인증 완료 후에는 해당 날짜의 체크리스트와 사진을 수정할 수 없다.
- 인증 완료 후에는 팀원 모두가 완료 상태를 확인할 수 있다.

### 당번 정책

- 팀원 누구나 오늘 당번을 변경할 수 있다.
- 당번이 바뀌면 인증 가능 대상도 새 당번으로 바뀐다.
- 당번이 인증하지 않으면 해당 날짜는 미완료로 기록될 수 있다.
- 자동 순번제, 요일별 당번, 반복 당번은 추가 예정 정책으로 둔다.

## 알림 정책

### 알림 종류

- 정기 알림: 오늘 인증할 시간임을 알려주는 알림이다.
- 콕 찌르기 알림: 팀원이 당번에게 보내는 즉시 리마인드 알림이다.
- 인증 완료 알림: 당번이 인증을 완료했을 때 팀원에게 완료 상태를 알려주는 알림이다.

### 정기 알림

- 정기 알림은 당번에게만 보낸다.
- 팀 모드에서 당번이 아닌 사람에게는 기본적으로 정기 알림을 보내지 않는다.
- 개인 모드에서는 개인 사용자 본인에게 정기 알림을 보낸다.
- 정기 알림 시간, 요일, 활성화 여부는 고도화 작업에서 구현한다.

### 콕 찌르기 알림

- 콕 찌르기는 팀 모드에서만 사용한다.
- 콕 찌르기 알림은 현재 당번에게만 보낸다.
- 예시 문구: "민지가 인증을 콕 찔렀어요"
- 인증 미완료 상태에서만 콕 찌르기를 사용할 수 있다.
- 인증 완료 후에는 콕 찌르기 버튼을 비활성화한다.
- 당번 본인은 자기 자신에게 콕 찌르기를 보낼 수 없다.
- 팀원 1명당 하루 최대 3회까지 콕 찌를 수 있다.
- 하루가 바뀌면 콕 찌르기 횟수는 초기화된다.

### 인증 완료 알림

- 팀 모드에서 당번이 인증을 완료하면 팀원에게 완료 알림을 보낼 수 있다.
- 완료 알림은 팀원들이 오늘 인증이 끝났다는 사실을 확인하도록 돕는다.
- 완료 알림의 기본 수신 범위는 팀원 전체로 검토한다.
- 완료 알림 수신 여부는 추후 사용자 설정으로 분리할 수 있다.

## 서버 고도화 정책

서버 데이터 모델 초안은 [server-data-model.md](./server-data-model.md)에 정리한다.

### Nest.js 도입 목적

- 사진 base64 LocalStorage 저장 문제를 해결한다.
- 팀, 멤버, 초대, 당번, 알림 정책을 서버에서 일관되게 관리한다.
- History와 인증 기록을 클라이언트 저장소가 아닌 서버 기준 데이터로 관리한다.

### 서버에서 관리할 주요 도메인

- users
- spaces
- space members
- invites
- checklist items
- assignments
- certifications
- certification photos
- notifications
- pokes

### 서버 전환 시 고려사항

- 기존 LocalStorage 데이터 마이그레이션 여부
- 사용자 식별 방식
- Apps in Toss 환경에서의 사용자 인증 방식
- 사진 업로드 저장소
- 사진 접근 권한
- 서버 기준 날짜와 클라이언트 기준 날짜의 차이
- 오프라인 또는 네트워크 실패 시 처리
- 업로드 실패 시 재시도 UX

## 추가 예정 정책

### 사진 고도화

- Nest.js 사진 업로드 API를 만든다.
- 사진 저장소를 정한다.
- 사진 URL 또는 photo key 기반으로 프론트 상태 구조를 바꾼다.
- 이미지 압축 방식을 정한다.
- History 사진 보존 기간은 기존 월 단위 정책을 유지한다.

### 알림 고도화

- 개인 정기 알림을 추가한다.
- 팀 정기 알림을 추가한다.
- 팀 콕 찌르기 알림을 추가한다.
- 팀 인증 완료 알림을 추가한다.
- 알림 수신 설정을 추가할 수 있다.

### 팀 고도화

- 팀 Space를 생성할 수 있게 한다.
- 팀원 초대 기능을 추가한다.
- 팀원 삭제 기능을 추가한다.
- 팀원 목록을 볼 수 있게 한다.
- 팀원 모두 설정 페이지에 접근할 수 있게 한다.
- 당번 지정 기능을 추가한다.
- 당번만 인증 가능한 권한 체크를 추가한다.

### 당번 고도화

- 1차는 수동 당번 지정으로 시작한다.
- 이후 요일별 당번을 검토한다.
- 이후 자동 순번제를 검토한다.
- 당번 변경 이력을 남길지 검토한다.

10. 인증 완료 알림 구현
11. History, 권한, 예외 상황 안정화

## 아직 결정이 필요한 항목

- 개인 모드와 팀 모드의 화면 진입 구조
- 개인 Space를 팀 Space로 전환할 수 있는지 여부
- 팀원 삭제 시 과거 인증 기록에서 사용자명을 어떻게 표시할지
- 당번이 팀에서 삭제되었을 때 오늘 당번을 어떻게 처리할지
- 인증 완료 알림을 기본 활성화할지 여부
- 콕 찌르기 3회 기준을 사용자별 Space 단위로 볼지, 사용자별 당번 단위로 볼지
- 서버 사진 저장소 선택
- 기존 LocalStorage 데이터 마이그레이션 여부
